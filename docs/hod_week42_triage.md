* Row 534 `pattern_data` still holds OCO#1 ids (tp a6f9b9ae, cancelled); OCO#3 ids were never persisted (the `if lo.get('trade_id')` branch ~l.2047 updates status/fill/qty only). After the 17:02 restart the registry was rehydrated from the stale row (17:04:18 "DB row holds 58 but broker holds 63"), so the engine did not know OCO#3 was live: 19:55:57-19:59:38 FORCE CLOSE failed 5x (available 0, held_for_orders 63), 20:00:01 "session closed ... no live liquidity" for QCMU.

* Mover queue (separate, not the crash cause): `queue.Queue(maxsize=5000)` hod l.361; producer `on_mover` (l.521-528, called for every symbol above the open on every scan, scanner l.1359) enqueues with dedup only in the consumer; consumer `_admit_movers` (l.678) drains <=500 per engine tick under `self._lock`. ROOT CAUSE: StopMonitor websocket unhealthy for >180 s tripped the scanner's own exit(1) breaker (cause of the WS death unlogged); the queue drops are a separate admission-throughput defect.
